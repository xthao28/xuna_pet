## Scope and implementation

- Inspected root, firmware and mobile Git status before editing. Existing dirty artwork, mobile UI, Session 2 adapter/store/tests and root documents preserved.
- `src/main.cpp`: `NvsSnapshotStore::begin` → `nextBoot` → `SnapshotStore::recover`; restore Ok/Migrated, allow Missing, route TooNew/Corrupt/MigrationFailed or storage/identity failures to ERROR_SAFE. Snapshot and identity writes are gated by successful recovery; `bootc` still increments before recovery as requested (the read-only safe policy concerns pet snapshots/identity).
- Identity: read/decode → `IdentityService::onBoot`; valid v1 migration gets `esp_random` entropy → prepare → durable `ident` write → accept. Identity is committed before initial v2 snapshot, so an interrupted initial snapshot write can retry with the same PetId. An Ok v2 snapshot with missing identity is safe rather than silently creating a replacement. PetId is logged, with no new BLE characteristic.
- Commit migrated v2 before enabling inputs; preserve `slot0/slot1`. Copy boot counter; cold-boot needs reset and `hasNeeds=false`.
- `BleManager` keeps GATT, one-central session tracking, queue, notifications and byte publication; adapter owns parsing/dedup and life/learning. Packet remains 12 bytes; capabilities remain `01 08 0f 00 0f 03 60 09` (bits 4/5/6 off).
- Loop uses adapter tick, GPIO14 idle, GPIO0 greeting with learning **false** (Happy), quiet preferred action, VisualIntent and five-minute commit-first checkpoint. Needs/activity/heap/render logs retained.
- Added adapter ERROR_SAFE checkpoint guard and regression test. No LifeEngine/BoardLearner instance or LifeStorage write on the production path; legacy snapshot codec/recovery still reads v1.
- Loop stack set to **16,384 bytes** before board trial; boot output scratch is static. Logs call `uxTaskGetStackHighWaterMark(nullptr)` after setup, opcode-3 handling and checkpoint; ESP-IDF reports bytes. No measured high-water values yet.
