# S12a + S12b — LifeSnapshot v2 codec and v1 migration (2026-10-15)

Status: **host-only, done criteria met for S12a and S12b**. Not wired into
production firmware (S13). Owner exception: S12a normally waits for D2; the
owner chose (2026-10-15) to run S12a/S12b before S11/D2 because the codec and
migration do not depend on the storage medium. D2 still decides the medium,
keys and LittleFS use in S13.

## Why the medium does not matter here

All three D2 options in plan §15 M04.4 store the snapshot as one bounded blob
(≤ 1,536 B) in A/B slots: (b) NVS keys `life0/life1`, (c) a larger NVS
partition, (d) a raw partition. The codec produces those bytes; the A/B rule
and recovery work on an abstract `ISnapshotStore`. S13 provides the adapter.

## Frozen layout (plan §7.5)

Header (12 B), little-endian, permanent contract:

| Offset | Field | Rule |
|---|---|---|
| 0 | `'X' 'U'` | same magic as v1 |
| 2 | `schema` u8 = 2 | > 2 → TooNew |
| 3 | `flags` u8 = 0 | non-zero → TooNew |
| 4 | `size` u16 | total bytes including the CRC trailer |
| 6 | reserved u16 = 0 | |
| 8 | `generation` u32 | A/B ordering, wrap-safe |
| 12 | sections | `{u8 id, u8 version, u16 length, data}` |
| end | CRC-32 (ISO-HDLC) | over every preceding byte |

Section id bit 7 = required (must be understood, else TooNew). Unknown
optional sections are skipped; each id appears at most once.

| Id | Section | Written | Bytes | Content |
|---|---|---|---|---|
| 1 | Counters (required) | always | 16 | `bootCounter`, `activeSeconds`, `eventSeqCommitted`, `feedbackCount` (u32) |
| 2 | Clock (optional) | after an accepted sync (S10 host part) | 6 | `lastTrustedUtcMinute` u32, `tzOffsetMin` i16 |
| 3 | Lifecycle | reserved (M06) | | |
| 4 | Needs (optional) | when RAM has needs | 4 | `energy`, `stimulation` (Q0.16) |
| 5 | Personality | reserved (M06) | | |
| 6 | Learner (required) | always | 8 + 10·cells | `LearnerV3Codec` payload; product 3 × 5 × 3 = 458 B |
| 7 | Habit | reserved (M05d) | | |
| 8 | Skills | reserved (tricks) | | |
| 9 | Dedup | reserved | | durable command idempotency |
| 10 | Pointers | reserved | | log/memory consistency |
| 11 | Episodes (optional) | always | 34 | v1 ring: count, next, 8 × {context, action, approved, source} |
| 12 | StatedPreference | reserved (M05c-A) | | `statedMass` |

Sizes: 536 B without needs, **544 B** with needs for the product learner.
Headroom: about 140 learner cells fit the budget (e.g. 4 × 5 × 7); the type's
maximum 4 × 5 × 8 does not, and `encode` refuses it.

Counters: `feedbackCount` is v1 `eventCount` (applied feedback, shown in BLE
life status). `eventSeqCommitted` stays 0 until the event log is persisted.
`bootCounter` is a copy of key `bootc`, filled by the S13 adapter.

## Load results

`decode`: Corrupt for any integrity or structure error (magic, size, CRC,
bad section framing, duplicate, missing Counters/Learner, invalid values);
TooNew only for an intact blob with a newer schema/flags or a required
section it does not understand; Ok otherwise. The output changes only on Ok.

`SnapshotStore::recover` (boot):

1. Any intact newer-schema v2 slot → **TooNew** (no rollback onto older data).
2. Newest valid v2 slot by generation → **Ok** (slots never mixed; unreadable
   other slot reported in `corruptSlots`).
3. Both v2 slots present and unreadable → **Corrupt** (no silent rollback).
4. At most one v2 slot present and unreadable (torn first write) or none →
   migrate the v1 slots → **Migrated**, v1 present but invalid →
   **MigrationFailed**, no v1 → **Missing** (fresh pet; a torn lone v2 slot
   is reported in `corruptSlots`). Changed during S18 preparation: an
   earlier draft returned Corrupt here, which would have sent a new pet into
   ERROR_SAFE after a power cut during its very first commit.

`SnapshotStore::commit`: generation + 1, write slot `generation % 2` (never
the newest valid slot). The caller adopts the staged copy only on success
(§9.5 commit-first); a retry targets the same slot.

## Migration v1 → v2

`migrateV1`/`fromV1` (pure, idempotent): counts → coarse learner cells with
the E10-C cap (ratio kept, mass ≤ 1/(1 − γ), raw count in `rated`); episodes
→ Episodes section; `activeSeconds`, `generation` kept; `eventCount` →
`feedbackCount`; needs absent (cold-boot policy). v1 slots are only read.

Recency: once v2 is wired, the discounted masses are stored directly, so the
board trial's "recency lost across reboots" limit goes away.

## Validation

- `test/test_snapshot_v2`: 16 tests. Roundtrip; size/budget; every single-bit
  flip → Corrupt with output unchanged; truncated/padded; TooNew rules;
  optional/required unknown sections; defaults for missing optional sections;
  structural errors; learner shape changes; the three golden v1 fixtures;
  idempotent migration; recovery rules incl. generation wrap; slot
  alternation; **torn-write sweep at every byte offset** (overlay and erased
  models) between two v2 generations and for the first v2 write after
  migration: recovery always returns exactly the previous state or the
  complete new one.
- Native 143/143 PASS (was 127). ESP32 build unchanged (RAM 48,328 B, Flash
  1,347,657 B; headers not linked yet); purity PASS.
- Pinned Xtensa g++ 8.4.0 `-std=c++11 -Wall -Wextra -Werror` compile smoke of
  the three headers: PASS.

## Findings for S13

- Stack: `-fstack-usage` on Xtensa shows `recover` 3,920 B plus nested
  `decode` 2,160 B (candidate copy of the snapshot). That is about 6 KB on
  the 8 KB Arduino loop stack. S13 should use static scratch/buffers.
- The NVS torn-write model differs from the byte-level worst case simulated
  here; S11/E5 power cuts remain the real evidence.
- Single unreadable v2 slot with the other missing falls back to v1. This is
  right for a torn first write but would hide a real loss of both v2 entries
  (NVS drops corrupt entries); S13 should log `corruptSlots`.
- Forget in v2: write an empty newer snapshot to both slots (as v1 does).
